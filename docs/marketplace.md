# 插件市场发布说明

## 展示信息

名称：炉石猫娘陪玩

英文名：Hearthstone Catgirl Companion

短描述：

> 只读理解炉石与酒馆局势，以事实和情绪驱动当前 NEKO 角色陪伴，并支持可追问的酒馆建议。

完整描述：

> 炉石猫娘陪玩只读 Hearthstone 的 Power.log，把普通对局与酒馆战棋局势提炼为本机实时状态、按需查询结果、情绪信号和低打扰的发言时机，再交给 NEKO 角色自然回应。酒馆支持实际观测的本地候选英雄、单排/双排、阶段回合、金币酒馆、商店/手牌/战团的动态类型、费用、金色状态与当前关键词、刷新/升本实际费用、八人大厅、上次观察的对手战团、结算名次和本机聚合统计。用户询问当前事实、英雄、阵容或节奏时，同轮只读工具会重新取得本轮完整状态与 evidence gate。插件不使用本地模板扮演角色，不注入、不读内存、不抓包、不操作游戏，也不编造无授权的全服胜率。

建议标签：

```text
炉石传说, 酒馆战棋, Hearthstone, Battlegrounds, 陪玩, 猫娘, 只读, 隐私
```

建议分区：陪玩 / 游戏

## 权限与通信

- 本地文件：增量读取 Hearthstone `Power.log`；首次恢复默认且最多在本机读取末尾 64 MiB，不会整体发送日志字节；
- 进程元数据：只查询精确名为 `Hearthstone.exe` 的进程镜像路径以定位同目录 `Logs`；不读进程内存、不扫描磁盘，路径不进入 LLM、Store、网络请求或插件遥测；
- 可选写入：用户点击“配置日志”后备份并更新 `log.config`；
- N.E.K.O 配置服务：唯一运行时设置来源，持久化面板显式保存的设置；用户填写的 `log_path` 会保存，自动发现的实际日志路径不会保存；
- Plugin Store：长期只保存不含完整单局历史的聚合酒馆统计，不读取或保存插件设置；SDK Store 生命周期由宿主管理；
- 子进程：仅按用户操作启动 Tk 透明诊断浮层，通过 stdin 接收显式测试消息；
- N.E.K.O：Hosted UI、唯一同轮只读 LLM tool、单一 Agent 查询入口、近期用户话语只读快照，以及定向主动 `respond`；
- 网络：每日固定 GET `hsbg.cards` 公共当前卡池，不携带牌局、卡牌 ID 或玩家信息；授权后由 N.E.K.O 当前模型提供商处理过滤字段。

## 审核要点

- 过滤后的局势共享默认开启，主动解说默认关闭；
- 主动解说必须同时开启局势共享，工具查询只要求局势共享；
- 本地代码不生成自动可见台词；角色回复来自 `visibility=[] + ai_behavior="respond"`；
- 完整局势只在本机维护；`hearthstone_live_state` 按问题返回有界聚焦视图，不持续发送牌局 `read` 分段；
- 若模型和 Agent 都未认领明确炉石问题，插件从官方近期话语记录取得实际角色并定向触发一次包含当刻聚焦快照的 `respond` 兜底；固定目标时过滤其他角色；
- 用户聊天后主动解说静默 30 秒，只有优先级 `>=9` 的关键事件可以绕过；
- 旁观模式不触发主动解说；
- 原始日志、玩家名和隐藏卡牌不会进入模型；
- 对手战团始终标记观察回合和“非当前”；
- 开局候选英雄只包含 `Power.log` 为本地玩家实际公开、未隐藏且未锁定的选项，不推断日志未观测的英雄；
- `hearthstone_live_state` 在酒馆模式可比较新鲜英雄选择阶段的实际候选；工具当次返回的新鲜完整招募商店可支持定性选牌，只有当前金币和商店实际费用完整时才支持精确可负担性与购买顺序，不把战斗或缓存状态包装成即时决策；
- 普通对战可在用户主动提问时共享本地玩家可见手牌并支持逐张取舍分析，但不宣称拥有完整合法操作枚举或隐藏信息；
- 全局 meta 明确不可用，官方静态规则标记 `is_win_rate_data=false`；
- 独立浮层只作显式诊断，不自动显示事件，也不声称显示角色最终文本；
- 所有可能改配置、启动子进程或删除统计的入口均需要用户操作。

## v0.2.0 变更说明

- PowerTaskList 成为动态实体、tag 与 block 的权威实时流；GameState 只提供模式元数据、新局边界、受限静态补全和终局信号，迟到镜像不能回滚实时商店、战团或可见性；
- 尾读周期降为 100 ms，并从最新完整 GameState 开局边界恢复；日志鲜度贯穿尾读、运行状态、场景 context 与 LLM 工具，过期快照不会冒充实时局势；
- 酒馆首个阶段信号可直接恢复招募或战斗状态；每场公开战斗开始时只在明确战斗标记后冻结首次确认的对手阵容，按对手保留最近一次观察，战斗召唤物不会污染历史；
- 新增实际观测的本地英雄候选和明确 team tag 驱动的双排队友标识，不补猜缺失信息；
- 英雄比较、具体购买和战斗点评分别受英雄候选、实时招募商店和公开阵容证据约束；历史聚合不再冒充最近一局；
- 隐藏实体在普通 zone、PLAY block 或变形引用中不会重新泄露旧 CardID、名称或属性，只有明确公开身份的日志事件可以恢复可见；
- 英雄选择完成改为本地 `MULLIGAN_STATE=DONE` 单调确认，乱序 INPUT 镜像不会重新打开候选；缺失 CARDTYPE 的战团实体必须具备合法站位或攻血证据；
- 面板每 500 毫秒串行刷新公开状态，配置、Store writer、Hosted UI、稳定 SDK smoke 和 tag Release 前置门禁增加事务与回归覆盖。
