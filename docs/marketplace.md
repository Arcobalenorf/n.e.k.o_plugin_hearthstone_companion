# 插件市场发布说明

## 展示信息

名称：炉石猫娘陪玩

英文名：Hearthstone Catgirl Companion

短描述：

> 只读理解炉石与酒馆局势，以事实和情绪驱动当前 NEKO 角色陪伴，并支持可追问的酒馆建议。

完整描述：

> 炉石猫娘陪玩只读 Hearthstone 的 Power.log，把普通对局与酒馆战棋局势提炼为情绪信号和低打扰的发言时机，再交给用户当前的 NEKO 角色自然回应。酒馆支持单排/双排、阶段回合、金币酒馆、商店战团、八人大厅、上次观察的对手战团、结算名次和本机聚合统计。用户询问阵容或节奏时，角色会先调用只读工具查询当前状态、带来源的当前卡池/卡牌事实、官方赛季资料和本机样本。插件不使用本地模板扮演角色，不注入、不读内存、不抓包、不操作游戏，也不编造无授权的全服胜率。

建议标签：

```text
炉石传说, 酒馆战棋, Hearthstone, Battlegrounds, 陪玩, 猫娘, 只读, 隐私
```

建议分区：陪玩 / 游戏

## 权限与通信

- 本地文件：增量读取 Hearthstone `Power.log`；首次恢复默认且最多在本机读取末尾 64 MiB，不会整体发送日志字节；
- 进程元数据：只查询精确名为 `Hearthstone.exe` 的进程镜像路径以定位同目录 `Logs`；不读进程内存、不扫描磁盘，路径不进入 LLM、Store、网络请求或插件遥测；
- 可选写入：用户点击“配置日志”后备份并更新 `log.config`；
- N.E.K.O 配置服务：唯一运行时设置来源，持久化面板显式保存的设置；用户填写的 `log_path` 会保存，自动发现的实际日志路径不会保存；
- Plugin Store：长期只保存不含完整单局历史的聚合酒馆统计，不读取或保存插件设置；SDK Store 生命周期由宿主管理；
- 子进程：仅按用户操作启动 Tk 透明诊断浮层，通过 stdin 接收显式测试消息；
- N.E.K.O：Hosted UI、固定目标时的隐藏场景 context、主动 `respond` 和只读 LLM tools；目标为空时不携带角色 ID 或跨消息合并键，由宿主逐消息路由；
- 网络：每日固定 GET `hsbg.cards` 公共当前卡池，不携带牌局、卡牌 ID 或玩家信息；授权后由 N.E.K.O 当前模型提供商处理过滤字段。

## 审核要点

- 默认数据同意和主动解说均为关闭；
- 主动解说必须同时具备数据同意，工具查询只要求数据同意；
- 本地代码不生成自动可见台词；角色回复来自 `visibility=[] + ai_behavior="respond"`；
- 仅显式固定目标时，场景进入/结束使用隐藏 `read` 和稳定 `coalesce_key`；目标为空时每条 `respond` 自带完整约束且不携带 `target_lanlan`/`coalesce_key`；
- 用户聊天后主动解说静默 30 秒，只有优先级 `>=9` 的关键事件可以绕过；
- 旁观模式不触发主动解说；
- 原始日志、玩家名和隐藏卡牌不会进入模型；
- 对手战团始终标记观察回合和“非当前”；
- 全局 meta 明确不可用，官方静态规则标记 `is_win_rate_data=false`；
- 独立浮层只作显式诊断，不自动显示事件，也不声称显示角色最终文本；
- 所有可能改配置、启动子进程或删除统计的入口均需要用户操作。

## v0.1.4 修复说明

- 自动识别正在运行的 `Hearthstone.exe` 安装位置，并从同目录 `Logs` 的多个会话文件夹中选择最后更新的 `Power.log`；支持插件先启动、炉石后启动；
- 自动发现只读取精确进程镜像路径元数据，不读进程内存、不扫描磁盘，路径不进入 LLM、Store、网络请求或插件遥测；
- 自定义游戏数据位置在诊断区拥有独立保存按钮和就地成功/失败反馈，清空并保存可恢复自动检测，不再要求滚回页面顶部；
- 路径保存仅提交 `log_path`，不会顺带覆盖未确认的授权、主动陪伴或浮层草稿；保存后立即重建读取器；
- 修复稳定 SDK 返回稀疏 profile 时其他配置可能暂时回默认值，以及配置 IPC 瞬时失败时现有日志来源被清空的问题。

## v0.1.3 修复说明

- 首次启用改为离线优先：炉石关闭、日志尚未生成或监听尚未启动时，都可提前保存本地模式、局势问答授权和主动陪伴设置；
- 将 `Power.log` 路径与日志配置下沉到页面底部诊断区，主流程只保留授权、主动陪伴选择和最终确认按钮；
- 区分“仅本地”“同意并开启局势问答”“同意并开启主动陪伴”三种最终动作与成功反馈；
- 修复 N.E.K.O 稳定版成功提交消息但返回空回执时被误判为失败的问题，并强化启动失败回滚和解说诊断；
- 自定义日志目录支持继续发现一至两层 Hearthstone 会话子目录中的 `Power.log`。

## v0.1.2 修复说明

- 修复部分稳定宿主没有活动配置 profile 时，面板保存返回 `ValidationError`；
- 优先使用官方 profile 配置接口，并在宿主未实现该接口时回退到持久运行配置接口；
- 保存后回读并核对提交字段，未确认落盘时明确报错，不把仅内存更新当作成功。

## v0.1.1 修复说明

- 插件目录和持久数据目录改用稳定 SDK 的 `config_dir`/`data_path`；

## v0.1.0 发布说明

以下内容用于当前独立仓库的首个 `v0.1.0` Release 和后续市场投稿。

- 新增 `hsbg.cards` 当前卡池/规则事实目录、固定来源缓存、离线降级与 UI 隐私开关；
- 酒馆建议会按当前商店、手牌、战团和英雄的 CardID 查询去重事实，由当前 NEKO 角色完成判断与表达；
- 将首次恢复窗口统一为 64 MiB，优先定位主 `GameState CREATE_GAME`；无法找到完整起点时进入 `bootstrap_incomplete`，不解说也不重复统计；
- 同步当前酒馆卡牌类型和双排 AI 模式，修复仅掉护甲的战果、Bob 商店误作对手、卖空战团回退旧场面及隐藏实体泄漏；
- 长局实体容量提高到 16384，并优先淘汰墓地、移除区和旧附魔；两份 12.3/32.9 MiB 真实酒馆日志均完整回放终局；
- 提示词的固定契约和 JSON 共同受 1800 字符硬上限约束，后台状态不再携带局势快照或本机绝对路径；
- 面板设置使用 N.E.K.O 配置服务作为唯一来源，Plugin Store 只保存酒馆聚合统计；
- 停机清理适配宿主 1.5 秒窗口，插件只停止自有统计 writer 而不关闭宿主 Store；统计初读失败时陪伴继续启动但禁止覆盖未知历史，清空失败会确认串行补偿；监听/浮层动作与设置保存按代次串行，浮层禁用和点击穿透均改为失败关闭；
- 修复英雄/Player 镜像导致升本和三连事件重复的问题，并以真实日志回放验证；
- 首启面板改为监听、公开局势授权、主动陪伴三步流程，技术诊断整体下沉；
- 补齐 36.2 与 36.2.2 官方来源链、hsbg.cards 署名和网络隐私披露；
- 新增酒馆战棋单排/双排公开状态解析和八人大厅；
- 新增金币、酒馆等级、商店、手牌、战团、冻结、当前对手与最终名次；
- 新增本机聚合赛季统计和只用于统计的安全 Store 写入线程；
- 新增战棋第 14 赛季官方静态资料与明确的数据来源边界；
- 新增 `hearthstone_battlegrounds_advice` 只读工具；
- 新增场景注入/恢复、结构化情绪 cue 和用户聊天静默窗；
- 删除自动本地角色模板与 HUD 回退，所有主动台词交给当前 NEKO 角色；
- 独立透明浮层降为显式诊断，不声称承载模型最终回复。
