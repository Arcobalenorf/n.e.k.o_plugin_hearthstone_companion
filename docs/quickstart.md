# 快速开始

## 1. 安装

当前版本请使用 GitHub Release 中的 `.neko-plugin` 文件；正式上架后也可从 N.E.K.O 插件市场安装。源码 ZIP 不能代替插件包。

启用并启动“炉石猫娘陪玩”后，日志监听、过滤后的局势问答以及开场/重连/结算回应默认可用；免打扰模式默认关闭，独立诊断浮层不自动启动。

## 2. 设置陪伴

不需要先打开炉石。进入插件主面板后，可以直接选择：

- “局势共享与对局回应”：默认允许 NEKO 通过同轮只读工具按需查询过滤后的玩家可见局势，并在新对局开始、重新接上和最终结算时各自然回应一次；关闭共享会一并停止这些模型能力。酒馆查询包含当前商店、手牌、战团、Choice 和经济关键字段，普通对战查询包含当前可见手牌与公开场面；
- “免打扰模式”：默认关闭，允许角色在少量关键局势主动回应；开启后避免中局事件触发角色插话，生命周期不受影响。

默认设置无需先保存即可提问。配置目标角色后，插件会用每个 segment 独立的稳定 key 定向维护有界、逻辑原子的 `hearthstone_live_segment_v2` 被动包；语义变化时更新，相同状态只做 30 秒续租，证据不属于当前回合/阶段的区域不会发送。每段用 `bundle=<revision>@i/n` 绑定整包，经真实宿主 parser 后不超过 180 tokens；整包受 3000-token selector 预算约束，v1、缺段、混版或 tombstone 后不得使用。未配置目标时，被动分段包、生命周期和主动解说都省略 `target_lanlan`，只依赖宿主恰好一个在线会话时的 targetless 路由；零个或多个在线会话都不会投递。普通问答只走官方同轮工具或 Agent 入口，插件不会在工具返回后另发 `respond`。调整后点击页面给出的绿色按钮即可保存局势共享和免打扰设置。关闭局势共享不影响本地日志监听，也不会改写免打扰偏好。

## 3. 启动炉石

打开炉石后，插件会自动识别正在运行的炉石安装位置，从多个会话文件夹中选择正在更新的游戏数据并连接。第一次启动时如果主面板一直提示等待游戏数据，请到页面底部“日志监听与诊断”点击“配置日志”。

插件会明确告诉你是否需要重启炉石：提示“请完全退出并重新启动炉石”时照做；提示“无需重启”时可以直接继续。通常不需要填写任何路径，也不需要在炉石游戏内寻找日志开关。只有自动连接失败时才填写自定义游戏数据位置，并在输入框旁点击保存。

进入酒馆后，面板会显示单排/双排、阶段、回合、金币、酒馆等级、商店、战团和八人大厅。英雄选择阶段会显示 `Power.log` 为本地玩家实际公开的候选，未观测或已锁定的英雄不会被补猜。对手战团若存在，会记录每场公开战斗开始时首次确认的随从、攻血和星级，按对手保留最近一次观察，并明确标记为历史而不是当前状态。

## 4. 开始提问与陪伴

启用插件后，实时状态保留在本机。角色收到普通聊天中的炉石问题后，可在首答同一轮调用实时工具重新读取本轮事实：当前回合和行动方使用无参数 `hearthstone_current_turn`，其他公开局势使用 `hearthstone_live_state`。高级设置中的 `target_lanlan` 限制定向被动上下文、生命周期和主动解说的角色；留空不会影响同轮工具或 Agent 查询，其他交付则只在宿主恰好一个在线会话时走 targetless 路由。例如：

综合工具会按可选原问题选择聚焦视图：构筑对面场面使用 `opponent`，酒馆商店使用 `shop`，升本/刷新使用 `economy`，综合出牌或购买建议使用 `strategy`。聚焦结果有固定大小上限，证据不足时会返回 `missing_evidence`，而不是用默认规则补猜实时值。

- “帮我看看现在酒馆玩什么流派比较好？”
- “这几个候选英雄选哪个？”
- “我现在该稳血还是升本？”
- “这个英雄我本赛季打得怎么样？”
- “帮我复盘刚才的最终名次和阵容信息。”
- “现在第几回合，轮到谁？”
- “看看我现在的手牌和场面，应该出什么牌？”

普通对战和酒馆共用同一权威快照；两个工具都会自动识别模式。综合结果包含金币、商店/手牌/战团、实际费用、金色状态、当前关键词、区域完整度、`hsbg.cards` 规则事实、官方赛季规则和本机样本。若问题需要全服胜率，角色会说明当前没有授权数据源，而不是编造。公共卡牌目录默认每日后台更新，不包含牌局或玩家数据；离线时会使用旧缓存并标记陈旧。

英雄选择建议只依据本局实际观测候选、公共英雄规则和带样本量的本机历史，不会编造全局胜率。新鲜完整商店、手牌、战团和目录规则足以回答定性的“哪张更值得考虑”；涉及“买得起哪些”“买完还剩多少”或“先买谁再刷新/升本”的精确经济与顺序时，还必须读到当前金币和当前商店所有卡牌的实际费用。费用不完整时角色应给定性方向并明确无法精算；战斗阶段或只有缓存状态时，则应说明缺少实时购买依据。

普通对战的当前回合/行动方必须在当次提问中调用 `hearthstone_current_turn`，资源、公开场面、具体手牌、Choice 与决策建议调用 `hearthstone_live_state`，不能直接沿用聊天历史里的旧状态。角色可以一起分析逐张出牌取舍，但日志不提供完整合法操作与目标枚举；当费用、目标或选项不完整时，角色应明确说明，不能把建议说成确定的最优解。对手未揭示手牌、奥秘身份和牌序始终不可见。

关闭免打扰并保存后，角色才会在三连、低血量或战斗等有情绪价值的中局时机主动说话。普通事件有 25 秒冷却，关键事件有 8 秒冷却；用户聊天后中局解说会安静 30 秒，只有重要事件会绕过静默窗。开场、重连和结算回应是独立生命周期，不使用这些冷却。

开启免打扰不会关闭生命周期回应、本机状态或查询入口。关闭数据共享会停止工具、Agent 和所有主动回应；入口会立即拒绝后续读取，尚未发送的生命周期待投递也会取消。免打扰偏好独立保留，重新开启共享后无需重新设置。

随包 `plugin.toml` 只提供安装默认值；N.E.K.O 原生配置服务是唯一运行时设置来源。高级诊断中显式填写的游戏数据位置会保存，自动发现的位置不会保存。状态刷新不会覆盖尚未保存的面板输入；Plugin Store 长期只保存聚合酒馆统计，其 client 生命周期由宿主管理。

## 5. 独立浮层诊断

“打开诊断浮层”和“测试解说”只用于验证透明窗口与消息通道。自动陪玩台词由 NEKO 宿主显示/播放，不会复制到该浮层，因为公开 Plugin SDK 不提供模型最终回复回调。

诊断浮层仅支持 Windows 和带 `tkinter` 的 Python，置顶、透明、点击穿透，并在炉石窗口不存在或最小化时隐藏。它不可用不会影响日志监听、工具或 NEKO 角色回复。

## 6. 停止与卸载

停止监听或停止插件会清理插件拥有的线程、待投递生命周期和子进程。卸载不会删除 Hearthstone 日志，也不会自动恢复 `log.config`；需要恢复时，在炉石退出后核对 `log.config.neko.bak` 再手动处理。

问题排查见[故障排查](troubleshooting.md)，数据范围见[隐私与安全](privacy-security.md)。
