# 隐私与安全

## 游戏侧边界

| 行为 | 是否执行 |
| --- | --- |
| 只读增量读取 Hearthstone `Power.log` | 是 |
| 用户确认后备份并更新 `log.config` | 是 |
| 注入 DLL、Hook、读进程内存或附加调试器 | 否 |
| 抓包、代理或解密游戏流量 | 否 |
| 自动点击、自动出牌或代打 | 否 |
| 推断隐藏手牌、未揭示奥秘或未来商店 | 否 |
| 上传原始日志 | 否 |

“技术上只读”不等于运营方或赛事已经授权。用户仍需遵守当前客户端、地区和赛事规则。

## 两个独立开关

`llm_data_consent` 允许只读 LLM tools 和场景上下文使用过滤后的公开局势。`llm_commentary_enabled` 只允许角色在事件触发时主动插话，并且必须以前一个同意为前提。

因此可以只开启数据同意：用户主动提问时工具可查询，角色不会主动解说。关闭数据同意会阻断工具读取和新的主动请求；只有显式固定目标并已建立隐藏场景时才发送恢复上下文。目标为空时插件不收集、保存或注入活动角色 ID，每条回复由宿主独立路由。

主动请求还受旁观模式、事件优先级、普通/关键冷却和 30 秒聊天静默窗约束。静默窗内只有优先级 `>=9` 的关键事件可以绕过；其他事件会被抑制。SDK 返回的 `submitted` 只表示本地接管请求，不证明模型已生成或用户已听到回复。

## 发送给模型的字段

普通对局公开字段：阶段、局数、回合、行动方、结果，双方公开生命/护甲/法力、手牌与牌库数量、奥秘数量、公开场面和最近公开出牌。

酒馆战棋公开字段：

- 单排/双排、招募/战斗阶段和回合；
- 我方金币、酒馆等级、冻结状态、当前商店、手牌和战团；
- 八名英雄的临时 player ID、英雄 card ID/名称、生命、护甲、酒馆等级、淘汰和名次；
- 当前对手 ID；
- 对手上次观察的公开战团及观察回合，明确标记为非当前状态；
- 任务、饰品、畸变、伙伴等已公开的机制 ID/进度；
- 事件类型、优先级、事实摘要和结构化情绪 cue；
- 当前赛季的官方静态规则与本机聚合统计。
- `hsbg.cards` 的数据提供方、补丁、检查时间、陈旧状态、当前池摘要，以及当前牌面已观察卡牌的规则文本、种族和关键词。

酒馆中的我方商店、手牌和战团来自用户自己可见的信息。普通构筑模式只共享我方手牌数量，不共享具体手牌身份。

以上字段由本机解析器从日志中提炼，再以有界结构发送。首次接入已有日志时默认且最多恢复读取末尾 64 MiB；这些字节只在本机逐行解析，不会作为日志片段或整体发送给模型。持续运行时只增量读取新增内容。

## 不发送或不持久化

- 原始日志行、完整日志文件和本地路径；
- 玩家昵称、BattleTag、账号 ID、邮箱或登录凭据；
- 对手隐藏手牌、未揭示卡牌、奥秘身份和牌库顺序；
- N.E.K.O 或 Hearthstone 的访问令牌；
- 屏幕截图、音频、键盘或鼠标输入；
- 未经过滤的实体对象；
- 完整单局历史或未经过滤的模型提示词。

插件不持久化完整单局历史。仅在用户授权时，才会把上文列明的有限近期公开事实（例如最近公开出牌、当前商店和上次观察的对手战团）随当次工具或解说上下文发送给模型。

## 本机统计

插件 Store 只保存聚合计数：赛季键、单排/双排、英雄 card ID、有效场次、Top 4/Top 2、第一名和名次总和。公开输出由这些计数计算比例并始终携带样本数。插件只管理自己的异步统计 writer；SDK Store client 及其关闭由 N.E.K.O 宿主管理。

不保存每局时间、对手、玩家名、账号、完整阵容或日志片段。用户可在面板明确确认后清空统计。

## 赛季与全局数据

`data/battlegrounds-season.json` 是随包静态文件，包含 Blizzard 官方补丁说明中的玩法规则、来源 URL、补丁号和验证日期；`is_win_rate_data=false`。

插件不访问 HSReplay 或 Firestone 的私有遥测，不抓取网页，不把静态规则或本机样本冒充全服 meta。工具以 `global_meta.available=false` 返回该边界，并要求角色禁止编造。

## 公共卡牌目录网络

默认每 24 小时访问 `https://hsbg.cards/api/v1/patches` 和带 `pool=current`、分页参数的 `/cards`。请求固定为 GET，不携带日志、玩家状态、卡牌 ID、昵称、账号或模型内容；服务端像普通网站一样可见用户 IP、请求时间和插件 User-Agent。可用 `card_catalog_network_enabled=false` 停止新的目录请求，已有缓存仍可离线使用并标记陈旧；关闭瞬间已经发出的单个请求可能正常结束，但不会继续下一页。

缓存只包含公共卡牌元数据，写入 N.E.K.O 分配给插件的 `cache_path()`；不写插件安装目录或 Store。响应体、条目、字段长度和重定向均受限制，更新通过原子替换完成。缓存损坏、超时、限流或服务错误不会影响 Power.log 监听和已有局势。

插件包不镜像或再分发 hsbg.cards 数据库。Card data: [hsbg.cards](https://hsbg.cards/about), subject to its [terms](https://hsbg.cards/terms). 卡牌名称、规则与其他 Hearthstone 游戏数据归 Blizzard Entertainment 所有。本项目与 hsbg.cards、Blizzard、网易均无隶属或背书关系。

## 数据去向

解析、状态和统计默认留在本机。开启数据同意后，过滤后的字段经 N.E.K.O 消息/工具通道交给用户配置的模型。模型可能位于本机或第三方服务；网络目的地、留存和训练政策由该 N.E.K.O 模型提供商决定。

安装默认值来自随插件发布的 `plugin.toml`，它不构成第二个运行时设置来源。用户在 Hosted UI 面板保存设置后，值由唯一的 N.E.K.O 原生配置服务持久化；插件不会把用户设置写回安装目录。用户显式填写的 `log_path` 会作为配置保存，自动发现的实际日志路径只在当前运行状态和本机诊断面板中使用，不会持久化，也不会发送给模型。

除上述公共卡牌目录外，插件不直连外部服务。独立诊断浮层只接收用户显式触发的测试消息，使用父子进程标准输入，不开放网络端口，也不会接收或伪造角色台词。

## 问题报告与合规

报告问题时优先提供插件/N.E.K.O 版本、`source_state`、`lines_seen`、`last_event_kind` 和 `last_error_code`。不要上传完整 `Power.log`；确需片段时先移除昵称、ID、设备路径等个人信息，并只保留最短复现片段。

国服、国际服和赛事要求可能变化。本项目不承诺平台许可或零封禁风险；收到客户端、反作弊、客服或赛事方冲突提示时应停止使用。将局势交给境外或第三方模型还可能涉及额外数据合规要求。本说明不是法律意见。
