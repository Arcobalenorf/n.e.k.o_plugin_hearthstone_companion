# 实时状态交付重构

当前设计见 [DESIGN.md](../DESIGN.md)，实现保持独立插件边界。

## 数据职责

CompanionMonitor 是状态唯一写入者，工具、面板和事件读取不可变公开快照。日志解析、隐私过滤、bootstrap、旁观、换源与既有新鲜度策略不在本次改动范围。

被动 read 只发送单条 core 概况，不默认同步完整商店、手牌或战团，不要求模型拼装分段。详细事实由 hearthstone_current_turn 和 hearthstone_live_state 查询；后者以显式 focus 选择视图，自然语言问题仅辅助选择。Agent 入口保留官方 finish 路由，复用工具的同源结果生成逻辑。

## 交付边界

- 工具只返回原 callback，不发独立主动消息补答。
- 发布概况使用稳定 key，拒绝不推进游标，撤权、停止、换源和过期时覆盖旧上下文。
- 配置角色时定向；未配置时仅依赖宿主恰好一个在线会话的 targetless 路由。
- SDK submitted 只证明提交，不证明宿主消费，更不证明角色回答。
- 保留官方文档所需的工具注册恢复，不增加私有宿主接口。
- 目录只补公共规则，不推测实际费用或隐藏信息。

## 生命周期与免打扰

开始、恢复和结束是共享开启时的固有行为，没有独立开关。免打扰默认关闭，开启后只抑制中局主动陪伴。生命周期保留有限去重和重试；主动 respond 必须自带事件事实，不依赖被动概况提供完整局势。

## 验证

分别证明公开快照正确、单条概况合规、工具 callback 返回详细事实、Agent 返回同源事实，以及生命周期提交。真实模型是否选择工具和最终回答正确率单独记录。不能把后台概况收到判为详细商店查询成功，也不能把历史 v0.4.0 发布证据作为当前源码的验证结果。
